# ADR 0001 · Python 3.12 fixado em .python-version

- **Status**: Aceito
- **Data**: 2026-11-20

## Contexto

O projeto precisa de uma linguagem com bom ecossistema para validação de dados (schemas de saída do LLM), testes e servidor HTTP. A versão do interpretador deve ser reproduzível entre máquina de desenvolvimento, CI e servidor.

## Opções consideradas

### Python 3.12

- **Prós**: Suporte amplo das bibliotecas escolhidas (FastAPI, Pydantic 2, SDK `openai`), wheels disponíveis para todas as dependências e presença em distribuições de servidor atuais.
- **Contras**: Não é a versão mais recente da linguagem; recursos novos do 3.13 e 3.14 ficam indisponíveis.
- **Custo**: Baixo: `uv` baixa e gerencia o interpretador.
- **Risco**: Baixo: versão madura, com correções de segurança ativas.

### Python 3.14

- **Prós**: Versão mais nova, com melhorias de desempenho e de mensagens de erro.
- **Contras**: Algumas wheels e pacotes de distribuição de servidor ainda ficam atrás; risco de instalar dependência compilando do código-fonte.
- **Custo**: Médio: tempo extra de build e de diagnóstico de incompatibilidades.
- **Risco**: Médio: falha de instalação no servidor ou no CI.

### JavaScript/Node

- **Prós**: Mesma linguagem do front-end, uma toolchain só.
- **Contras**: Validação de schema e testes de pipelines com LLM são menos maduros que Pydantic e pytest; o SDK e os exemplos de saída estruturada têm mais cobertura em Python.
- **Custo**: Médio: reimplementar validação e modelos tipados.
- **Risco**: Médio: menos referências para depurar saída estruturada.

## Decisão

Python 3.12, fixado em `.python-version` e instalado via `uv venv --python 3.12`.

## Por que vence

- **O que ganha e o que perde**: Ganha reprodutibilidade e compatibilidade com todas as dependências fixadas. Perde recursos de linguagem mais novos, que o projeto não usa.
- **Por que compensa**: Compensa porque o ganho de estabilidade supera qualquer recurso novo, e o PDF aceita Python ou JavaScript.

## Consequências

Todo o código mira 3.12. O CI e o servidor usam a mesma versão. Subir a versão no futuro é um ADR novo.

## Como verificar

`cat .python-version` retorna `3.12`; `.venv/bin/python --version` retorna 3.12.x; `pytest -q` passa nesse interpretador.
